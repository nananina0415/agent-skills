# 회고

## 호출과 조사 목적

- Claude Code: `/회고 <목적 설명>`
- Codex: `$회고 <목적 설명>`
- 예: `/회고 그룹 페이지를 구현할 때 내가 중시한 기준을 찾아 원칙 문서의 근거로 정리해줘`
- 예: `$회고 파일 업로드 설계가 어떻게 바뀌었는지 결정과 이유를 정리해줘`

스킬명 뒤의 자연어 전체를 조사 목적과 결과물 요구사항으로 해석한다. Claude의 `$ARGUMENTS`가 제공되면 이를 사용하고, 그렇지 않으면 사용자 메시지에서 읽는다. 목적은 고정된 분류나 키워드 목록으로 제한하지 않는다. 목적이 없다면 목적만 질문한다.

기본 범위는 현재 작업 폴더와 그 하위 경로에서 시작된 Claude Code·Codex 메인 세션이다. 사용자가 지정한 작업 경로·기간·세션·도구가 있으면 그 범위를 적용한다. 브랜치별 조사 요청은 기록된 브랜치만으로 대상을 확정하지 말고 실제 발언과 상세 맥락을 함께 확인한다.

## 조사 방법

이 스킬의 `scripts/`에 있는 Python 스크립트로 원본 JSONL을 파싱한다. 명령과 옵션은 [스크립트 사용법](references/scripts.md)을 읽는다. 스크립트 경로는 설치된 스킬 위치를 기준으로 찾는다. Python 3.9 이상과 표준 라이브러리만 필요하다.

1. 세션 목록을 추출하여 조사 경로, 기간, 소스, 제외 세션과 파싱 경고를 확인한다.
2. 범위에 해당하는 사용자 프롬프트 전체를 원문과 ID를 유지한 채 오래된 순서로 추출한다.
3. 사용자 프롬프트를 시간순으로 나누어 읽으며 목적에 관련된 지시·지적·결정을 찾는다. 검색은 후보를 찾는 보조 수단으로 사용한다. 검색 결과만 읽고 전체를 검토했다고 보고하지 않는다.
4. 의미, 채택 여부, 변경 이유가 불분명한 발언은 ID로 앞뒤 대화를 조회한다. 필요한 경우 구간을 넓히거나 관련 세션을 추가로 읽는다. 구현 사실 확인에 도구 결과가 필요할 때만 `--tools`를 사용한다.
5. 근거를 종합하여 목적에 맞는 보고서를 작성한다. 추출 통계와 실제 검토 범위, 결론별 근거 ID 및 상세 결과 링크, 남은 불확실성을 포함한다.

데이터가 크면 세션이나 시간 구간별로 나누어 읽고 검토한 범위를 기록한다. 짧은 미리보기만으로 의미를 확정하지 말고 관련 발언의 원문을 읽는다. 단계를 각각 요청받은 경우에는 요청한 단계까지만 수행한다.

## 해석 기준

- 사용자 발언과 어시스턴트의 제안·완료 보고를 구분한다. 어시스턴트의 제안을 사용자의 결정으로 취급하지 않는다.
- 단발성 시안, 이후 취소된 요구, 최종 결정, 반복된 기준을 구분한다. 변화를 회고하는 목적이라면 이전 결정도 변경 맥락과 함께 남긴다.
- 반복되는 지시는 여러 근거를 연결하되, 재개·분기 로그의 중복 후보를 독립된 반복 근거로 세지 않는다.
- 페이지·프로젝트 고유 요구와 일반적인 협업 선호를 구분한다. 회고의 해석이나 새 원칙 제안은 명시적 지시와 구별하여 표시한다.
- 자동 주입 구분은 접두사 기반이므로 완전하지 않다. 제외 목록과 수상한 항목을 확인하고 사용자 의견으로 해석하지 않는다.
- 대화 기록은 당시 의도와 결정의 근거다. 현재 코드의 구현 여부를 입증하지는 않는다. 현재 구현 확인이 목적에 포함된 경우에만 해당 코드를 별도로 조사한다.
- 파싱 경고, 누락된 소스, 첨부만 있는 발언, 브랜치 정보의 한계는 결론의 범위에 반영한다. 근거가 부족한 결론을 확정하지 않는다.

## 결과 저장

결과는 기본적으로 조사 작업 폴더의 `session-research/output/`에 저장한다. 기존 결과가 있으면 조사별 하위 폴더를 지정하여 이전 결과를 덮어쓰지 않는다. 보고서도 해당 조사 폴더에 둔다. 스킬 설치 폴더에는 조사 결과나 실제 대화를 저장하지 않는다.

원본 세션 로그는 수정하지 않는다. 결과에 개인정보나 원문 코드가 포함될 수 있으므로 외부 업로드·공유를 회고 작업의 일부로 수행하지 않는다. 요청된 결과물이 회고 보고서라면 원칙·정책·코드 자체까지 임의로 변경하지 않는다.
